# areve-backend

Сервер лендинга центра детской занятости «Արևէ», город Абовян.

Задача одна: **принять заявку из формы и не потерять её.** Заявка сохраняется
в базу, а центру уходит письмо.

Сайт — в репозитории **areve-frontend**.

## Стек

Express 5 · TypeScript (CommonJS) · PostgreSQL через Prisma 5 ·
express-validator · pino · helmet. Архитектура — модульный монолит.

## Запуск

Нужны Node ≥ 22 и PostgreSQL.

```bash
npm install
cp .env.example .env     # заполнить DATABASE_URL
npm run prisma:migrate
npm run dev              # http://localhost:5001
```

Пока переменные `LEADS_NOTIFY_TO` и `SMTP_*` пустые, письма не уходят —
заявки просто сохраняются, а в логе появляется предупреждение. Сайт при этом
работает полностью.

Для Gmail по SMTP нужен **пароль приложения**, а не пароль от почты: обычный
пароль Google по SMTP не пропустит. Создаётся в настройках аккаунта при
включённой двухэтапной проверке.

## API

```
POST /api/leads     создать заявку      201 + { id }
GET  /api/health    проверка живости    200 + { status: "ok" }
```

Полный договор с фронтендом — [docs/project-plan.md](docs/project-plan.md),
раздел 3: поля, ограничения, коды ошибок.

## Проверки

```bash
npm run check    # архитектура, типы, стиль
npm test         # договор с фронтендом
npm run verify   # всё вместе
```

`npm run check` запускается автоматически перед каждым коммитом.

**Границы модулей проверяет `tools/check-architecture.cjs`:** `shared` не знает
о модулях, в чужой модуль — только через его `index.ts`, круги между модулями
запрещены. Проверка должна быть зелёной после каждой правки.

## Персональные данные

В заявке лежат имя и телефон родителя. Отсюда правила, которые нельзя нарушать:

- **Имя и телефон не попадают в логи** — ни в логгере запросов, ни в тексте
  ошибки, ни в логах Prisma.
- В `details` ошибки валидации уходит только имя поля, без значения.
- IP в базу не пишется: счётчик ограничения частоты живёт в памяти процесса.
