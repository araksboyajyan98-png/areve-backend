## 3. Контракт для фронтенда

### `POST /api/leads`

```json
{
  "name": "Լիլիթ",
  "phone": "+374 77 123 456",
  "message": "Ուզում ենք այցելել",
  "website": ""
}
```

| Поле | Обязательное | Ограничение |
|---|---|---|
| `name` | да | 1–100 символов |
| `phone` | да | армянский номер; принимаются `+374 77 123 456`, `+37477123456`, `077 123456`, `77123456` |
| `message` | нет | до 2000 символов; пустая строка = не заполнено |
| `website` | нет | **ловушка для ботов**, поле скрыто стилями, человек его не заполняет |

Успех — `201`:

```json
{ "id": "32b72ecc-7d42-411b-a0fd-03280ae8773a" }
```

Отказ — конверт `{ error: { code, message, details? } }`:

| Код | Статус | Когда |
|---|---|---|
| `VALIDATION_FAILED` | 400 | поля не прошли проверку; в `details` — `[{ field, message }]`, **без значений** |
| `RATE_LIMITED` | 429 | превышен лимит заявок с адреса |
| `INTERNAL` | 500 | всё остальное |
| `NOT_FOUND` | 404 | неизвестный путь |

В `details[].message` лежит **имя поля** (`name`, `phone`, `message`) — это ключ,
по которому фронтенд достаёт перевод. Всем четырём кодам нужен перевод
в разделе `errors`.

### `GET /api/health`

`200` + `{ "status": "ok" }`. Для хостинга и мониторинга.

## 8. Правка после тестов (18.09.2026)

`tests/phone.test.mjs` в корне проекта нашёл дефект в `normalizePhone`:
номер на цифру короче — `095 313 63` — не отвергался, а превращался
в `+37409531363`.

Восемь цифр с ведущим нулём попадали в ветку «номер без кода страны», и ноль
уезжал в код оператора. Заявка сохранилась бы с несуществующим телефоном:
перезвонить по ней некому, а родитель увидел бы благодарность.

Починено: код оператора не может начинаться с нуля. Та же правка сделана
во фронтенде (`src/features/ContactForm/lib/phone.ts` в репозитории **areve-frontend**) — реализации
намеренно дублируются, и тест сторожит, чтобы они не разошлись.

Запуск: `npm test` в корне.
