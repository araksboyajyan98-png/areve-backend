# Бэкенд — журнал правок

Парный файл к журнал фронтенда в репозитории **areve-frontend**. Там — то, что видит пользователь; здесь —
то, что отдаёт сервер: контракт API, коды ошибок, статусы, поведение под
нагрузкой. Пока пуст — сервера ещё нет.

---

## Как пользоваться

Одна запись — одно замечание. Запись переезжает между разделами по состоянию,
а не переписывается заново.

```markdown
### BE-001 · Короткое название
- **Где:** `GET /api/items/:id` или `src/modules/items/items.service.ts`
- **Что не так:** фактическое поведение
- **Ожидается:** как должно быть
- **Как повторить:** запрос целиком — метод, путь, тело
- **Заметил:** дата
- **Состояние:** открыто | в работе | сделано | отклонено
```

Номера сквозные и не переиспользуются.

## Что стоит проверять

- **Конверт ошибки** — `{ error: { code, message } }` на **любом** отказе,
  включая 404 на несуществующем пути и битый JSON в теле.
- **Коды** — каждый `code`, который отдаёт сервер, имеет перевод на фронтенде.
  Расхождение — запись сюда.
- **Статусы** — 201 на создание, 404 на отсутствующее, 409 на конфликт,
  400 на валидацию.
- **Утечки наружу** — стек только в `development`; в `details` нет введённых
  пользователем значений; в тексте ошибки нет фрагментов SQL и параметров.
- **Логи** — у каждой записи есть `requestId`; в логах нет паролей, токенов,
  персональных данных.
- **Порядок маршрутов** — статичный путь объявлен до `/:id`.
- **CORS** — фронтенд ходит с разрешённого origin; отказ CORS попал в лог.
- **Списки** — есть предел выдачи; есть индекс под сортировку.
- **Границы модулей** — модуль не лезет в чужие таблицы напрямую.

## Что проверять именно здесь

Сервер принимает заявки с открытой формы, поэтому:

- **Телефон и имя не в логах.** Ни в `requestLogger`, ни в тексте ошибки, ни в
  уведомлении об упавшей отправке. Любое появление — запись сюда, с высоким
  приоритетом.
- **Нормализация телефона.** `+374 77 123 456` и `+37477123456` должны лечь в
  базу одинаково.
- **Ограничение частоты.** Превышение даёт `429` с кодом `RATE_LIMITED`,
  а не `500` и не молчаливое сохранение.
- **Ловушка для ботов.** Заполненное скрытое поле даёт `201`, но записи в базе
  нет. Отвечать отказом нельзя — бот поймёт.
- **Уведомление не ломает ответ.** Упавшая почта или мессенджер — заявка всё
  равно сохранена, ответ `201`, ошибка только в логе.
- **Пустое необязательное поле.** Заявка без сообщения проходит.
- **Длинные значения.** Имя длиннее 100 и сообщение длиннее 2000 символов дают
  `VALIDATION_FAILED`, а не обрезаются молча и не валят вставку.
