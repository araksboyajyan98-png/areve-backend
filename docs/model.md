# Бэкенд — модель данных

Проект: лендинг центра **Արևէ**, Абовян. Одна таблица — заявки из формы.

---

## 1. Где что лежит

```
prisma/
  schema.prisma       единственный источник истины по схеме
  migrations/         история изменений, в git
```

Клиент — `src/shared/config/prisma.ts`, один экземпляр `PrismaClient` на процесс,
логи Prisma уходят в `pino` (в dev — SQL на уровне `debug`).

**К Prisma обращаются только сервисы модулей.** Контроллеры — нет.
У каждой таблицы ровно один модуль-владелец.

---

## 2. Соглашения

### Именование

- Модель — единственное число, `PascalCase`: `Lead`.
- Поле — `camelCase`. Внешний ключ — `<entity>Id`.

### Обязательные поля

```prisma
id        String   @id @default(uuid())
createdAt DateTime @default(now())
updatedAt DateTime @updatedAt
```

`uuid` вместо автоинкремента: идентификатор не должен выдавать количество записей.

### Индексы

- Индекс под каждый частый запрос списка.
- Индекс под каждое поле, по которому фильтруют.
- Уникальность, важная для предметной области, объявляется в схеме
  (`@unique` / `@@unique`), а не проверяется только в коде: проверка в коде
  проигрывает гонку двух одновременных запросов.

### Типы

- Перечисления — `enum` в схеме, а не свободная строка.
- Время — `DateTime` в UTC; часовой пояс — забота фронтенда.
  Центр работает по `Asia/Yerevan` (UTC+4) — это важно при чтении дат заявок.
- Необязательное поле объявляется `?` осознанно: `null` должен что-то значить.
- Деньги (если появятся тарифы) — не `Float`, а целое в драмах.

### Удаление

Заявка не удаляется физически при обработке — меняется `status`.
Удаление по сроку хранения — отдельный скрипт в `src/scripts/`.

---

## 3. Миграции

- `npx prisma migrate dev` — **только локально**; на сервере `migrate deploy`.
- Миграция попадает в git в той же правке, что и изменение `schema.prisma`.
- **Переименование модели генерирует `DROP TABLE` + `CREATE TABLE`** — такая
  миграция пишется вручную через `ALTER TABLE … RENAME`, иначе данные пропадут.
- Добавление обязательного поля в непустую таблицу — двумя шагами: сначала
  необязательное с заполнением, потом `NOT NULL`.

## 4. Схема

```prisma
generator client {
  provider = "prisma-client-js"
}

datasource db {
  provider = "postgresql"
  url      = env("DATABASE_URL")
}

/// Заявка из формы обратной связи на лендинге.
model Lead {
  id        String     @id @default(uuid())
  name      String     @db.VarChar(100)
  phone     String     @db.VarChar(32)
  message   String?    @db.VarChar(2000)
  status    LeadStatus @default(NEW)
  createdAt DateTime   @default(now())
  updatedAt DateTime   @updatedAt

  @@index([status, createdAt])
  @@index([createdAt])
}

enum LeadStatus {
  NEW        // поступила, никто не смотрел
  CONTACTED  // с родителем связались
  ARCHIVED   // закрыта: пришли, отказались или дубль
}
```

## 5. Сущности проекта

### Lead — заявка

- **Владелец:** модуль `leads`
- **Зачем:** родитель оставил телефон, чтобы ему перезвонили. Одна запись —
  одно обращение, а не один ребёнок и не один договор.
- **Поля:**

| Поле | Тип | Что значит |
|---|---|---|
| `id` | `String` uuid | идентификатор |
| `name` | `String(100)` | имя родителя, как он его написал; обязательное — так в форме |
| `phone` | `String(32)` | телефон; обязательное, единственный способ ответить |
| `message` | `String(2000)?` | вопрос или желаемый день визита; в форме поле необязательное |
| `status` | `LeadStatus` | стадия обработки |
| `createdAt` | `DateTime` | когда пришла |
| `updatedAt` | `DateTime` | когда меняли статус |

- **Связи:** нет.
- **Индексы:** `[createdAt]` — список «сначала новые»; `[status, createdAt]` —
  список необработанных.
- **Уникальность:** нет. Один и тот же родитель может обратиться дважды, и это
  не ошибка. Дубли разбираются статусом `ARCHIVED`, а не ограничением в базе.
- **Удаление:** статусом; физическое — по сроку хранения, скриптом.

### Чего в модели намеренно нет

- **IP и User-Agent.** Заманчиво для борьбы со спамом, но это ещё одни
  персональные данные к имени и телефону. Ограничение частоты держим в памяти
  процесса, в базу не пишем.
- **Согласие на обработку.** Появится, если на форме будет галочка — тогда поле
  `consentAt DateTime`, а не `Boolean`: важно, **когда** согласились.
- **`source`** (какая кнопка привела на форму). Кнопок три: hero, адаптация,
  тарифы. Полезно, если центр захочет знать, что работает, — но пока никто
  не просил.

### Нормализация телефона

Телефон хранится **как ввёл пользователь**, приведённый к одному виду:
только цифры и ведущий `+`, пробелы и дефисы убраны. Иначе `+374 77 123 456`
и `+37477123456` в списке выглядят как два разных человека.

Нормализует сервис при создании, не контроллер и не база.
